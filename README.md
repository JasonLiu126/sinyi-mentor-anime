# 信義新星｜正式版公開展示

GitHub Pages 展示版包含首次適性測驗、商圈地圖、九欄社區勘查、分次儲存草稿、店長審核示範、角色收藏及公開小學堂。

知識小學堂的稅務第 1～3 關使用公開練習題。三關皆嵌入國稅局的 YouTube 公開影片，無法載入時使用自製補課短片。作答、補課進度、草稿及審核示範皆儲存在各訪客自己的瀏覽器。

## GitHub Pages

在 Settings → Pages 選 Deploy from a branch，分支 main、資料夾 /(root)。

## V4「遊戲大廳風」改版

外觀改成手機遊戲大廳：預設首頁是主城，底部導覽 5 格（冒險地圖、角色、主城、夥伴、試煉）。資料、計分、審核與存檔邏輯沿用原本程式，V4 只包裝既有函式、重排畫面與換外觀。

| 檔案 | 內容 |
|---|---|
| `theme-v4.css` | 色票、字體、共用元件與各頁 V4 外觀（最後載入） |
| `v4-adapters.js` | 只讀既有資料，換算職業、等級、主線、夥伴等顯示數值 |
| `lobby-v4.js` | HUD、導覽、主城、夥伴編隊 |
| `journal-v4.js` | 冒險日誌、懸賞板、委託詳情 |
| `map-v4.js` | 冒險地圖、探索副本（情報拼圖） |
| `handbook-v4.js` | 角色頁（雷達、裝備欄、天賦樹） |
| `showcase-v4.js` | 召喚祭壇、夥伴名冊、參觀同事主城 |
| `academy-v4.js` | 試煉之塔、實戰對練 VS／戰鬥／結算 |

### 任務檢核模擬（日報同步／店長審核）

任務設定與系統參數集中在 `content-v4.js`（預設值＋PM 後台核准的變更）：

- 📊 日報判定：新人照常在公司日報系統填寫、店長在該系統審核；本系統每天同步 2 次已審核的數字，從接任務當天起累計，達門檻自動完成。原型用店長後台「日報同步」頁模擬同步。
- 👑 店長判定：日報無法判定的任務，新人送審（擋手機、身分證、Email 等個資）→ 店長在後台核可或退回；退回達上限任務結束。
- 經驗由難度決定（小 20／中 40／大 80），依權重分到 1～3 項能力；新人已接取的任務沿用接取當時的設定，不受改版影響。
- 新人 APP 主城右上 🔔：遊戲內通知（核可、退回、新指派、日報同步完成、開放重測、指派快到期）。
- 另外記錄：覺醒試煉作答（`sinyi-v4-quiz-history-v1`）、使用時間（`sinyi-v4-usage-v1`）、AI 對練各面向分數與評語（`sinyi-v4-practice-v1`，不存對話）。

## 店長後台（manager.html）

店長看自己分店的新人，區主管看到的一樣但可切換整區（側欄「示範身分」切換；正式版由 SSO 判斷）。「本機新人」讀寫這台瀏覽器的新人 APP 存檔，其他新人是虛構示範資料（唯讀）。

| 功能 | 內容 |
|---|---|
| 總覽 | 新人一覽（等級、陪伴期第幾天、各路線進度）、待審數、逾期提醒 |
| 任務審核 | 👑 任務送審與指派任務回報，核可或退回（需原因） |
| 社區勘查審核 | 9 欄勘查內容，核可或退回補正 |
| 新人能力與紀錄 | 能力、覺醒試煉紀錄與開放重測、AI 對練紀錄、任務紀錄 |
| 日報同步 | 同步紀錄；Demo 用表單模擬公司日報同步 |
| 指派任務 | 判定方式、難度、1～3 項成長能力、期限；上限依總部設定；不發金幣 |
| ↺ 重置 Demo | 清除這台瀏覽器所有 `sinyi-*` 資料，已開著的新人 APP 自動重新載入 |

## PM 後台（pm.html）

| 功能 | 內容 |
|---|---|
| 任務範本 | 修改系統任務名稱、判定方式、日報門檻、難度、成長能力；存草稿或送 PO 核准，可設生效日 |
| 系統參數 | 指派上限、審核期限、退回上限 |
| PO 核准 | PO 核准或退回；不能核准自己送出的修改 |
| 版本紀錄 | 每次核准一個版本，可還原（還原也要核准） |
| 名單 | 輸入員工編號加入 PM／PO |
| 使用統計 | 使用時間、任務數／完成／未完成、完成花費時間、AI 對練；匯出 Excel 可開的 CSV |

尚未接資料庫：所有資料存在同一台瀏覽器的 localStorage（`sinyi-v4-content-v1` 為內容變更與名單）。之後接資料庫時替換各檔案的讀寫函式（`v4cLoad`／`v4cSave`、`mLoad`／`mSave`、`v4VerifyLoad`／`v4VerifySave`）。
